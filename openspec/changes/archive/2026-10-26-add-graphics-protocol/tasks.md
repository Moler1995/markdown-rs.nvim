## 2. The sequences and the payload

- [x] 2.1 Add `M.osc_sequence(position, cols, rows, data)` returning the exact bytes: the CSI cursor move to `position` 1-based, then `ESC ] 1337 ; File=inline=1;width=<cols>;height=<rows>;preserveAspectRatio=0;doNotMoveCursor=1:<data> ESC \`. Verify with a headless test asserting the whole string for a known position, box and payload, byte for byte.
- [x] 2.2 Add `M.kitty_sequence(position, cols, rows, id, path)` and `M.kitty_delete(id)` returning the exact bytes: `ESC _ G i=<id>,a=T,t=f,p=<id>,c=<cols>,r=<rows>,C=1,q=2;<base64 path> ESC \` and `ESC _ G a=d,d=I,i=<id>,q=2 ESC \`. Verify with headless tests pinning both strings, including a path with non-ASCII bytes.
- [x] 2.3 Add `M.plan(ref, base, tier)`: refuse an `http://`, `https://` or `data:` destination; use an absolute path as it is and join a relative one to `base`; stat it and refuse when it is not a readable file. For `'osc'`, refuse a file over `MAX_BYTES`, read it with `vim.uv.fs_read` and base64-encode it once; for `'kitty'`, keep the path and read nothing. Verify with headless tests over temporary files: a readable one with both tiers, a missing one, a directory, a URL, a `data:` URI, a relative destination with and without a base, and a file one byte over an injected cap.
- [x] 2.4 Add `M.place(win, graphic)` and a module-level `M.send` that a test replaces. `place` takes the window's content position, width and height and sends one sequence for the graphic's transport; the production `send` is `nvim_ui_send`, guarded so an editor without it is a no-op. Verify with a headless test that each transport produces exactly one send of exactly the expected bytes.
- [x] 2.5 Carry `preserveAspectRatio=0` in the OSC sequence. WezTerm defaults the parameter to true, and with it the given height is ignored and derived from the width, so the file was letterboxed and the popup's last rows and columns showed the character artwork. With both dimensions given and preservation off, the file fills the same cell box the artwork was laid out in. Verify with the exact-bytes check in 2.1 and by hand in 5.3.
- [x] 2.6 Move the placement in past the window's frame. `nvim_win_get_position` returns the corner of a float's *border*, not its first text cell — measured with `screenpos`, a float opened at `row = 5, col = 10` with `border = 'rounded'` draws its first text cell at screen row 7, column 12 — so the image covered the border's top and left and left one cell of artwork showing beside and below it, which is the misalignment the third hand check reported. Take the offset from the window's own `border`, which is 1 for every style that draws a corner cell and 0 for `'none'` and `'shadow'`. Verify with a headless check that a bordered window's placement names the `screenpos` cell rather than the reported position, that a borderless one is unchanged, and that the popup's own placement in 3.3 is asserted against `screenpos`.

## 3. The popup

- [x] 3.1 Keep the image reference in `preview.image_block` instead of discarding it, and compute the plan in `M.preview` before the render: pass it to `preview.view` and to `preview.open`. Verify with a headless test that an image block carries its reference and that a URL reference yields no plan.
- [x] 3.2 In `preview.view`, request `image_animation` only when the popup will not show a graphic: never for `'osc'`, and for `'kitty'` only so the frames exist to decide with. Verify with a headless test asserting the engine arguments for an image popup with no plan, with an OSC plan and with a Kitty plan.
- [x] 3.3 In `preview.open`, decide whether to place: no graphic when the document carries an animation with more than one frame on a transport that cannot play files. Otherwise flush with `:redraw`, place the image, then `nvim__redraw({ cursor = true, flush = true })` under `pcall`, and record the graphic on the popup. Verify with a headless test using a replaced sender: a still image on either transport sends once; an animated image on `'kitty'` sends nothing and keeps its playback; the popup keeps the artwork in its buffer and its window geometry.
- [x] 3.4 Confirm a graphic popup binds neither the pause nor the frame-step key and starts no timer, which 3.2 gives for free on `'osc'`: with no frames in the document there is nothing to bind. Verify with a headless check that the popup buffer's keymaps contain neither key, and that an `'osc'` popup has no animation.
- [x] 3.5 Re-place the graphic on `VimResized` and `WinResized`, debounced by `resize_debounce`, at the window's current position and from the cached record. Verify with a headless test that one resize event burst produces exactly one further send with the same bytes, and that a closed popup produces none.
- [x] 3.6 On a Kitty placement, send the delete for the placement's identifier immediately before closing the window, in every close path — `M.close`, the `WinClosed` handler — so no image outlives its popup. Verify with a headless test using a recording sender that close emits exactly one delete naming the placed id, that a second close emits none, and that an OSC popup emits none.
- [x] 3.8 While a graphic is placed, bind the popup buffer's wheel and vertical scroll keys (`<ScrollWheelUp/Down/Left/Right>`, `<C-e>`, `<C-y>`, `<C-d>`, `<C-u>`, `<C-f>`, `<C-b>`, `<PageUp>`, `<PageDown>`) to a no-op. A hand check found that rolling the wheel over a still image's popup erased the image, because an OSC placement is removed from the cells a repaint touches; with the image covering the whole interior there is nothing to scroll to. The close key and the other keys are untouched, and a popup that keeps its artwork (Kitty animation) or has no placement keeps the wheel. Verify with a headless check asserting those mappings on a still image's popup for both transports, and their absence on the animated-Kitty and fallback popups.
- [x] 3.9 Freeze the configured sideways scroll keys (`keymaps.scroll_left`, default `<C-h>`, and `keymaps.scroll_right`, default `<C-l>`) with them. The third hand check reported the same failure for these: they scroll the viewport sideways, that repaint removes an OSC placement exactly as a wheel notch did, and the picture turned back into character artwork. They are bound on every popup before the placement, so the freeze is a re-binding, and nothing is lost because an image is laid out at the popup's inner width — its window is as wide as its content. Verify with a headless check that the mapping on a graphic popup is the no-op rather than the `zh`/`zl` scroll, for both transports, and that a popup without a placement (animated Kitty, fallback) keeps the scrolling map.
