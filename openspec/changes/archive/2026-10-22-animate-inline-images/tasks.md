## 1. Engine: animation frames behind a flag

- [x] 1.1 Add `--image-animation` to the CLI in `engine/src/main.rs` and thread it into `ImageOptions`; verify `md-render --help` lists it, and a render without the flag of a document containing an animated GIF is byte-identical to the previous binary's output.
- [x] 1.2 Add `animations: Vec<WireAnimation>` (with `#[serde(skip_serializing_if = "Vec::is_empty")]`) to `WireDoc` in `engine/src/wire.rs`, holding `source`, `start`, `rows` and `frames: [{ delay, lines }]`; verify a unit test serializes a document without animations with no `animations` key, and one with animations carries the exact shape from `design.md` D2 while `version` stays 1.
- [x] 1.3 In `engine/src/image_art.rs`, decode GIF and animated-WebP frames with the `image` crate's `AnimationDecoder` (`GifDecoder::into_frames`, `WebPDecoder::into_frames` after `has_animation`), keep the first frame as the static artwork, and take each frame's delay from `Delay::numer_denom_ms`; verify unit tests against committed fixtures: a 3-frame GIF and a 3-frame WebP yield all 3 frames (frame 0 equal to the static artwork) with the recorded delays, a still PNG and a still WebP yield none. (The frame list includes frame 0 so its delay is carried; the static artwork stays in `lines`.)
- [x] 1.4 Enforce the caps from `design.md` D7 — at most 256 frames and 64 MP of cumulative decoded pixels — as all-or-nothing: an image over either bound renders as its first frame with no animation data; verify unit tests for 257 frames and for a frame count that crosses 64 MP at 16 MP per frame, plus one image exactly at each bound that still animates.
- [x] 1.5 Route every frame through the existing sample→quantize→encode path at the document's own width, height and encoding, and verify (a) no line of any frame is wider than the requested width, (b) every frame occupies exactly the first frame's row count, (c) frames share the document's `StyleTable` and interns no duplicate style, and (d) two renders with the flag are byte-identical.
- [x] 1.6 In `engine/src/document.rs`, record `start` (the line count before the artwork push) and `rows` (the lines pushed), attach `source`, and push frame lines through the same `Layout::push`; verify a layout test on a one-line document places the animation at the reference's line range and that `lines[start .. start + rows]` equals the first frame.
- [x] 1.7 Measure a `--image-animation` render of a 100-frame 480×270 GIF at 126 columns, record engine time, JSON size and Lua-parse-equivalent decode time; confirm the engine stays under the 500 ms target from `design.md` D8 and record the numbers in the change's review notes — if it does not, stop and report before continuing.
  - Measured 2026-10-22, `target/release/md-render.exe`, 100 frames × 480×270 at width 126 (`rows` 35): engine **589 / 402 / 403 ms** over three runs (the first is cold; steady state is 402 ms, under the 500 ms target), JSON **1,373,989 bytes**, `vim.json.decode` with `luanil = { object = true }` **3.8 ms** (best of three).
  - After the cap rose to 64 MP, the same command on `Desktop/test.gif` (189 frames × 640×360, 43.5 MP, `rows` 35 at width 126): engine **1084 / 1084 / 1071 ms**, JSON **3,528,964 bytes**, `frames` 189, `animations_limited` empty. The target above is stated for the 100 × 480×270 case and is still met there; this file costs roughly 2.5× the pixels and 1.9× the frames.
- [x] 1.8 Document the `animations` field in `docs/md-render-format.md` (shape, `source`/`start`/`rows`, delay in milliseconds, first frame stays in `lines`, field omitted when absent) and verify the example matches real output.
- [x] 1.9 Distinguish a refused animation from a still image on the wire: carry `Artwork::animation_limited` into `WireDoc.animations_limited` (the reference's source lines, omitted when empty); verify wire tests for the field and its absence, and a document test that a 257-frame GIF names its reference and carries no frames.

## 5. Preview popup: the image alone, playing

- [x] 5.1 Extend `preview.locate` with the `image` kind, carrying the reference's own source text; make `preview.render_block` render that reference alone with `--base` from the document and a budget of the popup's inner width and height; verify a headless test finds only the image in the popup for `text ![a](x.png) more` and that an `off`-encoding render of the reference is requested.

- [x] 5.2 Make `<CR>` on image artwork open the popup (staying on the existing mermaid/table behaviour elsewhere) and verify a headless test that the popup opens with the image and that `<CR>` still falls through off the artwork.
