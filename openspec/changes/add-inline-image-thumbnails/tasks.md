# Tasks

## 1. The card encoding, in the engine

- [ ] 1.1 Add `Card` to `ImageEncoding` in `engine/src/image_art.rs` and to the clap value list, placed after the pixel encodings with a doc comment in the file's style. The card takes its box from the same `cell_grid` call the braille encoding uses, at the same bounds, so both hold the same columns and rows. Verify with a unit test that a card's line count and widest line equal braille's for the same fixture at the same bounds, and that `cargo run -p md-render -- --image-encoding card --width 80 <fixture>` exits zero.
- [ ] 1.2 Draw the card in `image_art.rs`: the whole box in the theme's raised surface as the background, the middle row carrying one caption in the muted foreground, centred and truncated to the box's width, and a box with no room for a cell falling back as an unrenderable image does. Build the caption as the resolved file's name, suffixed with ` · <width>×<height>` when the header reports a size. Verify with unit tests for the caption string, its centring at odd and even widths, its truncation, and the empty-box fallback, plus one snapshot of a card for a fixture.
- [ ] 1.3 Size an over-limit picture from its header under the card encoding. `load` currently returns nothing before the header is consulted for a file over 16 MiB; read the header first for the card, keep the file-size and pixel limits binding decoded pixels, and keep the alt text for missing, unreadable, unsupported and remote references. Verify with tests: a file over 16 MiB with a readable header is a card of the header's box; a picture declaring more than 16 megapixels is a card; the same two under braille remain alt text; a 0-byte file and an SVG remain alt text.
- [ ] 1.4 Add card coverage to the engine tests: a corpus fixture document rendered with `--image-encoding card` compared against its braille render for line count and source attribution, and a sweep that no card line exceeds the requested width. Verify with `cargo test -p md-render --test corpus` and `cargo test -p md-render --test dependencies` (no new crate).
- [ ] 1.5 Document the encoding where the engine's options are described — the clap help in `engine/src/main.rs` and the encoding list in `docs/md-render-format.md` if it names the encodings — stating what a card is, that it occupies the artwork's box, and that it is chosen by name. Verify the help text lists `card` and `cargo test -p md-render --test wire_format_doc` still passes.

## 2. The thumbnail mode, in the engine

- [ ] 2.1 Add the `thumbnail` subcommand to `engine/src/main.rs`: a positional source path, `--box <cols>x<rows>`, `--out <path>` and `--background <#rrggbb>`. It writes one file and nothing to standard output, and every refusal exits non-zero with a diagnostic on standard error. Verify with integration tests over the binary: the expected argument set produces a file, and a missing argument exits non-zero naming it.
- [ ] 2.2 Implement the thumbnail in `image_art.rs`: decode the picture under the existing limits, compute the output box as `cols × k` by `rows × 2k` with `k` giving about 640 pixels of width and the box bounded to two megapixels, scale to fit without distortion, centre, and fill the remainder with the requested background. Verify with tests on a synthetic picture: the output's width-to-height ratio is `cols` to `2 × rows`, the letterbox band is exactly the background colour, the output decodes to fewer pixels than the source, and the same request twice is byte-identical.
- [ ] 2.3 Choose the output format by transparency — PNG when the picture has transparent pixels, JPEG otherwise — using the encoders the compiled `image` features already carry. Verify with tests asserting the first bytes of one output of each kind.
- [ ] 2.4 Refuse the inputs the mode cannot serve — a missing or unreadable file, an unsupported format, a box with no room for a cell, a box whose size is over the pixel bound, an output path it cannot write, a picture over the decoding limits — each non-zero, each naming the offending path on standard error, none writing standard output. Verify with one test per refusal.
- [ ] 2.5 Document `thumbnail` beside the render options in `engine/src/main.rs` and in `docs/md-render-format.md`'s note on auxiliary modes, saying it is what the plugin paints inline and that it is the only stage with a decoder. Verify `cargo run -p md-render -- thumbnail --help` lists all four arguments.

## 5. Inline placement, in the plugin

- [ ] 5.1 Add the thumbnail request to `lua/md-render/graphics.lua`: a function taking the source path, the cell box and the background, which runs the engine's `thumbnail` mode into a `vim.fn.tempname()` file, reads it, deletes it, and returns the bytes or nil. Cache the result in memory keyed by absolute path, file length, mtime, columns and rows, bound the cache and evict least-recently-used entries. Verify with headless tests over a replaced runner: one request per key, no second request on a repeat, a new request after the file's mtime changes, and the temporary file gone after the call.
- [ ] 5.2 Compute a block's rectangle from the rendered document — the run of display rows attributed to the reference's source line, and the widest of them — and its screen origin from `screenpos`, and decide visibility as the whole rectangle lying inside the window's visible rows. Verify with headless checks using `screenpos`: an unshifted block, a block scrolled half out (no placement), and a block with `scrolloff` in play.
- [ ] 5.3 Place on settle: register `WinScrolled`, `WinResized`, `CursorMoved`, `CursorMovedI` and the re-render path behind one debounce, place each wholly visible image block once per burst, and send nothing for blocks that are not. Verify with headless tests counting sends: one send per block for a burst of scroll events, none for a partly visible block, one for each of two visible blocks, and a re-place after the popup closes.
- [ ] 5.4 Send the right payload per transport: the thumbnail bytes through the OSC sequence at the block's origin; the original path through the Kitty sequence with a per-placement identifier, deleted when the block leaves the window or R is closed. Verify with headless tests pinning the exact bytes of both sequences for a known block and asserting the delete.
- [ ] 5.5 Make every failure quiet: an unreadable file, an engine refusal, a nil answer, or a placement the terminal ignores leaves the card, sends no message, and changes no keys. Verify with headless checks that a failing runner produces no send and no `vim.notify`, and that the buffer's keymaps and content are untouched.
